# 设备验证套件

一条命令跑完发版前应过的设备场景，输出逐项 PASS / FAIL 的报告。此后每次发触碰同步或 hook 的版本都应重跑；报告末尾的「原始证据」留有关键日志、哈希与清单，复核结论不用再上设备。

## 跑法

```bash
# 前提：OptIcon_A16_root 已启动并开机、装了被测的调试包、hook 已注入系统界面、宿主空闲内存 ≥ 6GB
bash scripts/device/run_suite.sh                 # 全部（约 25 分钟，含一次重启）
bash scripts/device/run_suite.sh --only d1,d4    # 只跑指定场景
bash scripts/device/run_suite.sh --skip d6b      # 跳过（d6b 最慢；d5 / d6 需要外网）
```

报告在 `tests/device-reports/<时间>/REPORT.md`（不入库），截图、界面树与各阶段日志在同一目录。退出码非零 = 有检查点失败，或还原没做成。

- d8 只负责采集与几何断言，审美判读另由具备视觉能力的模型或人完成。2.0 倍字体下「软键盘弹出后按钮是否被挡」目前只采集不定级，结论由读图给出。
- d6 要求开跑前 5 分钟内 hook 没有自同步过（事件触发的两次同步之间有最小间隔），否则「打开后即同步」那一条会超时。
- d8 临时打开「硬键盘时也显示软键盘」，并以系统的输入法状态为准断言软键盘确实弹出，之后才采「键盘弹出」的画面；结束时还原。
- 被测包必须是调试包：套件依赖只在调试构建里存在的测试接收器与「允许明文流量」声明。

## 场景

| 场景 | 验证什么 | 依赖 |
|---|---|---|
| d1 | 没有自定义源时添加首个 PICP 源：落盘格式不被迁移覆盖、列表归属、冷启动后仍在、编辑回显、选项间距与标题位置 | — |
| d2 | 升级前被选为当前应用图标源的自定义源：迁移后仍在列表、选中不变 | — |
| d3 | 无法判定的旧源：两个列表都显示并带提示、同步被拒、编辑必须选格式、选定后只留一处 | — |
| d4 | 四种坏源（纯文本 / 无匹配 / 条目边界截断 / 数据中间截断）：如实失败、图标库逐字节不变、无残留 | 本机测试源 |
| d5 | 上游撤销在两条读取通道上生效：未自定义的包镜像被删、启用了自定义的包镜像保留、hook 本地缓存里两者的图标都被删、新通知不再显示旧图标、全程不重启系统界面 | 外网、测试接收器 |
| d6 | 自动更新开关：点行标题即切换、不重启即生效、关闭即停、偏好与共享文件不一致时自动对齐 | 外网 |
| d6b | 锁屏密码变体：重启后解锁前不工作、解锁后自行恢复（会设 PIN 并重启一次） | 外网 |
| d7 | 首次同步的体积确认只弹一次；同步中取消后状态行不是错误色 | 本机测试源 |
| d8 | 2.0 倍字体、软键盘弹出、旋转、深色模式下的对话框采集；单选行高 ≥ 48dp、选项之间有间距、标题不越出本行 | — |
| d9 | 共享目录被整体移走再放回：系统界面放掉失效的目录监听，目录回来后重新建立 | hook 已注入 |

## 它会对设备做什么

- 只操作核身过的实例（AVD 名 + 机型都对才动手），序列号在重启后会重新查找。
- 开始前备份：应用偏好文件、图标库（`tar`，留在设备 `/data/local/tmp/`，结束时删除）、显示与输入法设置、通知权限状态。
- d5 会往规则库、共享目录与系统界面的本地缓存里各放一个测试图标（包名 `com.android.shell` 与 `io.suite.customized`），并以 `com.android.shell` 的身份发两条通知。
- d9 会把共享目录 `Download/OptIcon` 改名移走几秒钟再改回来（结束时若没改回来会兜底）。
- 结束时（包括中途失败）自动还原以上各项、删掉测试图标与临时文件、清除 PIN；还原本身的检查也计入报告。只删套件自己创建的共享目录镜像。

## 本机测试源

`serve.py` 只监听 `127.0.0.1`（默认 28765；8765 在本机不可绑定）。模拟器带着全局代理，访问 `127.0.0.1` 的请求经代理落回宿主，所以源地址写 `http://127.0.0.1:<端口>/`，不要用 `10.0.2.2`。生成的样本在 `payloads/`（不入库）。
