# 设备验证套件

一条命令跑完发版前应过的设备场景，输出逐项 PASS / FAIL 的报告。此后每次发触碰同步或 hook 的版本都应重跑；报告末尾的「原始证据」留有关键日志、哈希与清单，复核结论不用再上设备。

## 跑法

```bash
# 启动实例（带 adb 服务端口：套件固定用自己的 adb 服务，见下）
ANDROID_ADB_SERVER_PORT=5038 emulator -avd OptIcon_A16_root -no-snapshot -no-boot-anim

# 前提：OptIcon_A16_root 已开机、装了被测的调试包、宿主机不忙（见下面的「宿主机负载」）
bash scripts/device/run_suite.sh                 # 全部（约 25 分钟，含一次重启）
bash scripts/device/run_suite.sh --only d1,d4    # 只跑指定场景
bash scripts/device/run_suite.sh --skip d6b      # 跳过（d6b 最慢；d5 / d6 / d10 / d12 / d13 / d14 需要外网）
```

报告在 `tests/device-reports/<时间>/REPORT.md`（不入库），截图、界面树与各阶段日志在同一目录。退出码非零 = 有检查点失败，或还原没做成。

- **宿主机负载**：开跑前和每个场景之前各看一次宿主机，CPU 连续三次采样（间隔 10 秒）都 ≥ 60% 就不跑（报告里记下数值）。只按 CPU 判定：可用内存说明不了问题——宿主机被游戏占满的那晚可用内存还有 4.6GB，反而比平时一台虚拟机加构建守护进程跑着的时候多；提交率与硬缺页只记录，没有在故障现场标定过。2026-11-25 宿主机在跑游戏时跑过一轮：虚拟机被饿到，下面「设备状态」里说的那种故障整轮都在，失败和被测包无关。确要在这种时候跑，设 `SUITE_ALLOW_LOADED_HOST=1`。
- **设备状态**：每次进入应用前确认有窗口持有焦点、锁屏没有挂着，不满足就等；等不到就把输入分发器、窗口、活动栈、负载、崩溃记录、日志尾巴和截图留在报告目录的 `diag-*/` 里并终止整轮。起因是套件开跑时会重启系统界面进程——框架在它不在的这段时间里把锁屏置为显示中，新进程起来之后才撤掉；虚拟机被饿着时新进程起不来（启动超时被杀），锁屏就一直挂着，之后每一次点击都被输入分发器丢掉，界面上却什么都看不出来。
- **场景完整**：场景的导航步骤失败就当场停下，后面的检查不再执行（否则「没有开始同步」「图标库不变」这类检查会凭空通过）；每个场景之后记一条「跑到了最后」，中途返回的在报告里查得到。
- **adb 服务隔离**：套件用自己的 adb 服务端口（默认 5038），启动实例时带同一个环境变量。多个会话共用默认端口的服务时，别的会话重启它会让这边的设备操作落空（2026-11-25 整跑时 d1 就这样失败过）。实例登记在默认端口上时套件找不到它，会直接说明原因。
- d8 的几何与位置断言是硬检查；审美判读另由具备视觉能力的模型或人完成。
- d6 要求开跑前 5 分钟内 hook 没有自同步过（事件触发的两次同步之间有最小间隔），否则「打开后即同步」那一条会超时。d14 同理。
- 规则库的场景（d10b / d11 / d12）要用本机测试源冒充上游的官方发布清单，提供的包是上游 2026-11-26 那一份真实资源包：`tests/upstream-2026-11-27/bundle/anip-bundle-e98c906.zip`（不入库，取法见同目录 README）。没有它测试源起不来，套件在准备阶段就停。
- 这台模拟器挂着实体键盘，输入法默认只显示侧边工具条。d8 临时打开「有实体键盘时也显示软键盘」并断言弹出的是**贴底键盘**（占屏幕底部 ≥ 400px），再检查添加 / 编辑对话框的按钮都在键盘上方；结束时还原。输入法在实例重启后头一次弹出时才是贴底键盘，被收起之后变成工具条或悬浮键盘——整跑时 d8 排在会重启的 d6b 之后所以能测到；**单独跑 d8 之前先重启实例**。
- 被测包必须是调试包：套件依赖只在调试构建里存在的测试接收器与「允许明文流量」声明。

## 场景

| 场景 | 验证什么 | 依赖 |
|---|---|---|
| d1 | 没有自定义源时添加首个 PICP 源：落盘格式不被迁移覆盖、列表归属、冷启动后仍在、编辑回显、选项间距与标题位置 | — |
| d2 | 升级前被选为当前应用图标源的自定义源：迁移后仍在列表、选中不变 | — |
| d3 | 无法判定的旧源：两个列表都显示并带提示、同步被拒、编辑必须选格式、选定后只留一处 | — |
| d4 | 四种坏源（纯文本 / 无匹配 / 条目边界截断 / 数据中间截断）：如实失败、图标库逐字节不变、无残留 | 本机测试源 |
| d5 | 上游撤销在两条读取通道上生效：未自定义的包镜像被删、启用了自定义的包镜像保留、hook 本地缓存里两者的图标都被删、新通知不再显示旧图标、全程不重启系统界面 | 外网、测试接收器 |
| d6 | 自动更新开关：点行标题即切换、不重启即生效、关闭即停、偏好与共享文件不一致时自动对齐 | 外网 |
| d6b | 锁屏密码变体：重启后解锁前不工作、解锁后自行恢复（会设 PIN 并重启一次） | 外网 |
| d7 | 首次同步的体积确认只弹一次；同步中取消后状态行不是错误色 | 本机测试源 |
| d8 | 2.0 倍字体、贴底软键盘弹出、旋转、深色模式下的对话框：按钮始终可点（键盘弹出时在键盘上方）、内容可滚动、底板不透明（截图等画面稳定）；单选行高 ≥ 48dp、选项之间有间距、标题不越出本行 | — |
| d9 | 共享目录被整体移走再放回：系统界面放掉失效的目录监听（只放一次、不留孤儿），目录回来后重新建立 | hook 已注入 |
| d10 | 真实上游经官方发布通道同步：状态行带上游版本（标签 + 日期）；已知答案 924 条 = 814 个位图 + 10 个 SVG 渲染 + 100 个别名，缺失与未解析为 0；别名包的图与目标包逐字节相同；SVG 渲染出合规的 PNG（≤150px）；两类包都有共享目录镜像。两类图标各发一条通知，留状态栏与通知栏截图——审美判读交给具备视觉能力的模型或人，套件只判「hook 替换了小图标」 | 外网、测试接收器 |
| d10b | 彩色 SVG（自定义规则源，本机包 = 官方包 + 一个红色圆形 SVG + 一个别名）：渲染保留原色、别名得到自己的一份；拿这张彩色图发通知，状态栏里新出现的像素必须全部无彩色——证明带透明通道的彩色位图和上游的单色位图走同一条着色路径。收尾回到内置源，两个测试包随之撤销 | 本机测试源、测试接收器、外网（收尾） |
| d11 | 上游没有新版本：第二次同步只取清单（本机源的请求计数：清单 1 次、包 0 次），状态行「已是最新」带条数与上游版本；快照逐字节不变、不重建、不做收尾、无残留。收尾回到真实上游 | 本机测试源、外网（收尾） |
| d12 | 包核对不上：清单里的 sha256 与包不符 → 退回整库归档（真实上游）；状态行如实，不带上游版本（整库没有版本可报）；快照的版本记录为整库。收尾回到真实上游 | 本机测试源、外网 |
| d13 | 没有代理的网络：去掉模拟器的全局代理后同步，成功或如实报「下载失败」都算过——批 UP 去掉了前置探测，不再有「网络不可用」的误拦。设备上两个域名的直连状态码记进报告 | 外网（可能不可达） |
| d14 | 总开关关 + 自动更新开：用自动更新开关的切换把 hook 的循环叫醒几轮，总开关关着时不自同步（开关文件本身为开）；总开关重新打开后自同步恢复 | 外网 |

## 它会对设备做什么

- 只操作核身过的实例（AVD 名 + 机型都对才动手），序列号在重启后会重新查找。
- 开跑时重启一次系统界面进程，让 hook 随当前安装的包重新加载。
- 开始前备份：应用偏好文件、图标库（`tar`，留在设备 `/data/local/tmp/`，结束时删除）、显示与输入法设置、通知权限状态。
- d5 会往规则库、共享目录与系统界面的本地缓存里各放一个测试图标（包名 `com.android.shell` 与 `io.suite.customized`），并以 `com.android.shell` 的身份发两条通知。
- d9 会把共享目录 `Download/OptIcon` 改名移走几秒钟再改回来（结束时若没改回来会兜底）。
- d10 抹掉规则库快照的版本记录（`source.json`），让这一次一定重新下载；d10 / d10b 把规则库里的某张图临时放成 `com.android.shell` 的共享镜像并发一条通知（用完经媒体库删除）。
- d11 / d12 往偏好文件里写一个只有调试包才读的键，把内置规则源的官方发布清单临时指到本机测试源；之后的场景和结束时的偏好还原都会把它清掉。
- d13 临时去掉模拟器的全局代理，场景结束（含中途失败）时改回原值并核对。
- d14 关一次总开关再打开；结束时核对它与开始前一致。
- 结束时（包括中途失败）自动还原以上各项、删掉测试图标与临时文件、清除 PIN；还原本身的检查也计入报告。只删套件自己创建的共享目录镜像。

## 本机测试源

`serve.py` 只监听 `127.0.0.1`（默认 28765；8765 在本机不可绑定）。模拟器带着全局代理，访问 `127.0.0.1` 的请求经代理落回宿主，所以源地址写 `http://127.0.0.1:<端口>/`，不要用 `10.0.2.2`。生成的样本在 `payloads/`（不入库）。

规则库相关的端点（批 UP）：`/anip-release.json` 是官方发布通道的清单，指向 `/anip-bundle-aaaaaaa.zip`——上游 2026-11-26 那份官方资源包原样，只换了标签，所以已知答案（924 条）对真实上游和本机清单都成立；`/anip-extra.zip` 在这份包上多两个清单条目（红色圆形 SVG 与一个别名），给自定义规则源用。`payloads/mode.txt` 写 `badsha` 时清单里的哈希故意对不上（d12），套件每轮从「正确」开始、d12 结束时改回。调试包里对应的大门是偏好键 `e2e_anip_manifest_url`：只有调试包读它（`BuildConfig.DEBUG`），正式包没有任何入口能写；清单地址只认 https 或回环地址上的明文。
